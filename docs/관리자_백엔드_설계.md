# 관리자 페이지와 문의 저장을 위한 서버 구조 제안

현재 홈페이지는 정적 사이트라서 관리자 페이지와 문의 저장 기능이 없습니다. 이 문서는 나중에 서버를 붙일 때의 구조를 제안합니다. **아직 구현된 것은 없습니다.**

## 왜 지금은 관리자 페이지가 없는가

관리자 페이지는 로그인, 데이터 저장, 파일 올리기가 필요하고, 이 세 가지는 서버에서만 안전하게 처리할 수 있습니다. 브라우저 저장소(localStorage)만 쓰는 화면은 관리자 본인 PC에서만 바뀌어 보이고 방문자에게는 반영되지 않으므로 관리자 시스템이 될 수 없습니다. 비밀번호를 HTML이나 JavaScript에 적는 방식도 누구나 볼 수 있어 쓸 수 없습니다.

## 선택지

| 방식 | 내용 | 맞는 경우 |
| --- | --- | --- |
| A. 현재 방식 유지 | 제작사가 `data/*.json` 을 수정하고 빌드해 올림 | 수정이 월 몇 회 이하일 때. 추가 비용 없음 |
| B. 문의만 외부 서비스 연결 | 폼 수신 서비스 주소를 `inquiry.endpoint` 에 입력 | 문의 저장과 메일 알림만 필요할 때. 서비스 약관과 개인정보 국외 이전 여부 확인 필요 |
| C. 자체 서버 구축 | PHP 8.2 + CodeIgniter 4 + MySQL (사내 개발 표준) | 고객사가 직접 글을 올리고 문의를 관리해야 할 때 |

회의록에서 「주 1회 이상 칼럼 업데이트」와 「고객사가 직접 관련 링크를 추가·삭제」를 목표로 했으므로, 운영이 시작되면 C로 가는 것이 맞습니다.

## C안 구조

사내 개발 표준(PHP 8.2 + CodeIgniter 4 + MySQL 5.6)을 따릅니다.

```
프로젝트 루트/
├── app/
│   ├── Config/            Routes.php, Filters.php, Database.php
│   ├── Controllers/
│   │   ├── Admin/         Auth, Dashboard, Strain, Patent, Product, Achievement,
│   │   │                  Partner, PartnerCase, Notice, Column, Media, Inquiry, Setting
│   │   └── Api/           Contact (문의 접수)
│   ├── Models/            StrainModel, PatentModel, … , ContentRelationModel, InquiryModel
│   ├── Views/admin/       layout.php + 목록·입력 화면
│   ├── Filters/           AdminAuth.php
│   └── Database/Migrations/
├── public/                현재 사이트 (index.html, css, js, images, uploads)
├── writable/
└── .env                   저장소에 올리지 않음
```

### 테이블

모든 테이블에 `id`, `created_at`, `updated_at`, `deleted_at` 을 둡니다.

| 테이블 | 주요 컬럼 |
| --- | --- |
| `admin_users` | login_id, password_hash, name, last_login_at |
| `strains` | slug, name, species, species_ko, former_name, category, origin, summary, research(JSON), note, is_published, sort_order |
| `patents` | number, status, title, title_en, reg_date, app_number, app_date, summary, cert_image, cert_pdf, is_published |
| `products` | slug, name, company, category, summary, tech_text, image, official_url, is_published, sort_order |
| `achievements` | slug, type, year, title, source, summary, url, is_published |
| `partners`, `partner_cases` | 현재 `data/partners.json` 과 같은 항목 |
| `notices`, `columns`, `media` | 현재 `data/board.json` 과 같은 항목 + is_pinned, is_main |
| `content_relations` | from_type, from_id, to_type, to_id (다대다 연결, id 기준) |
| `inquiries` | company, name, phone, email, type, subject, message, file_path, agreed_at, status, memo |
| `settings` | skey, svalue (로고, 주소, 연락처, 쇼핑몰 주소, 메뉴 이름) |
| `ci_sessions` | 데이터베이스 세션 |

현재 JSON의 `id`·`related` 구조가 `content_relations` 와 같은 모양이므로, JSON을 그대로 읽어 넣는 이전 스크립트를 만들 수 있습니다.

### 관리자 화면과 사이트를 잇는 방법

현재의 생성기(`src/build.mjs`)를 그대로 씁니다.

1. 관리자가 글을 저장한다.
2. 서버가 DB 내용을 `data/*.json` 형태로 내보낸다.
3. 생성기를 실행해 `public/` 의 HTML을 다시 만든다.

방문자는 계속 정적 HTML을 받으므로 속도와 검색 노출이 유지되고, 화면 디자인도 다시 만들 필요가 없습니다. 호스팅에서 Node.js를 쓸 수 없으면 생성기를 PHP 뷰로 옮기는 작업이 추가로 필요합니다.

### 문의 접수

- `POST /api/contact` — CSRF 필터 적용, 필수 항목·이메일 형식·동의 여부를 서버에서 다시 검증
- 저장에 성공한 경우에만 `{ "status": true, "message": "...", "data": null }` 응답. 현재 `js/contact.js` 가 이 형식을 이미 처리합니다.
- 첨부파일: jpg/png/pdf 허용, 5MB 이하, 파일명 재생성, `public/uploads/` 밖의 비공개 폴더에 저장
- 관리자 메일 알림은 저장이 끝난 뒤 발송. 메일 발송 실패가 접수 실패가 되지 않도록 분리
- 문의 목록은 `adminAuth` 필터 안에서만 조회

### 보안

- 비밀번호는 `password_hash()` 로 저장, 로그인 실패 횟수 제한
- 관리자 주소 전체에 `adminAuth` 필터, 모든 입력 화면에 `csrf_field()`
- 출력은 `esc()`, DB는 Query Builder 사용
- DB 계정, 메일 계정은 `.env` 에만 두고 저장소에는 `.env.example` 만 올림
- 문의 개인정보는 보유 기간이 지나면 삭제하는 예약 작업 필요

### 필요한 것

- PHP 8.2와 MySQL을 쓸 수 있는 호스팅 (GitHub Pages로는 불가)
- 도메인 연결과 HTTPS
- 메일 발송 계정 (SMTP)
- 개인정보 보유 기간과 보호책임자 확정
