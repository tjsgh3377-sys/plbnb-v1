# PLBNB 공식 홈페이지

주식회사 피엘비앤비(PLBNB) 공식 홈페이지 소스입니다. 고객사가 확정한 B안(DNA 이중나선 메인 비주얼)을 바탕으로 전체 메뉴와 서브페이지를 구성했습니다.

서버 프로그램이 필요 없는 **정적 사이트**입니다. HTML 파일을 그대로 올리면 열리므로 GitHub Pages나 일반 웹호스팅 어디에나 배포할 수 있습니다.

## 구성

| 위치 | 내용 |
| --- | --- |
| `data/*.json` | **콘텐츠 원본.** 회사 정보, 메뉴, 균주, 특허, 적용 제품, 연구 성과, 협력사, 게시판 |
| `src/` | 사이트 생성기. `data/`를 읽어 HTML을 만듭니다 (Node.js, 외부 패키지 없음) |
| `index.html`, `company/`, `business/`, `partners/`, `board/`, `support/`, `shop/` | **생성된 페이지.** 직접 고치지 않습니다 |
| `css/`, `js/`, `images/`, `assets/` | 스타일, 스크립트, 이미지, 영상 |
| `sitemap.xml`, `robots.txt` | 빌드할 때 자동 생성 |
| `docs/` | 고객사 확인 요청 목록, 변경사항, 관리자 백엔드 설계 |
| `_reference/mib/` | 디자인 참고용 타 업종 시안 (사이트에 연결되지 않음) |

## 실행

```bash
node src/build.mjs
```

```bash
python -m http.server 8765
```

첫 명령은 `data/`와 `src/`의 내용으로 페이지 전체를 다시 만듭니다. 끊어진 내부 링크가 있으면 오류로 알려 줍니다. 두 번째 명령을 실행한 뒤 브라우저에서 `http://localhost:8765` 를 열면 확인할 수 있습니다.

## 콘텐츠 수정 방법

관리자 페이지 대신 `data/` 폴더의 JSON 파일을 고칩니다. 고친 뒤에는 반드시 `node src/build.mjs` 를 실행하고, 변경된 파일 전체를 서버에 올립니다.

| 하고 싶은 일 | 고칠 파일 |
| --- | --- |
| 주소·전화·이메일·대표자, 메뉴 이름(예: 리즈 스토리), 쇼핑몰 주소, 문의 수신 주소 | `data/site.json` |
| 회사 연혁, 대표이사 인사말·경력·수상, 스토리 본문과 사진 | `data/company.json` |
| 균주 추가·수정 | `data/strains.json` |
| 특허 추가·수정, 특허증 이미지 | `data/patents.json` |
| 적용 제품 추가·수정 | `data/products.json` |
| 논문·과제·인증 | `data/achievements.json` |
| 협력사, 협력 사례 | `data/partners.json` |
| 공지사항, 연구 칼럼, 언론 보도 | `data/board.json` |

공통 규칙:

- 각 항목의 `id`는 다른 항목과 연결하는 고유값이자 상세페이지 주소입니다. 한번 정하면 바꾸지 않습니다. 제목은 자유롭게 바꿔도 연결이 유지됩니다.
- 항목에 `"published": false` 를 넣으면 사이트에서 빠지고, 그 항목으로 향하던 연결도 함께 사라집니다.
- 게시판 글은 날짜 순으로 자동 정렬됩니다. 메인페이지의 「연구 소식」에도 최신 글이 자동으로 나옵니다.
- 이미지는 `images/` 아래에 넣고 경로를 적습니다. 비워 두면 「이미지 준비 중」 자리로 표시됩니다.

### 균주·특허·적용 제품 연결

연결은 한쪽에만 적으면 됩니다. 예를 들어 특허에 관련 균주를 적으면 균주 상세페이지에도 그 특허가 자동으로 나타납니다.

```json
"related": { "strains": ["pl9988"], "products": ["bulgaris"], "media": ["yna-20151216"] }
```

쓸 수 있는 종류는 `strains`, `patents`, `products`, `achievements`, `media`, `columns`, `cases` 입니다. 없는 id를 적으면 빌드할 때 경고로 알려 줍니다.

### 연구 칼럼 쓰기

`data/board.json` 의 `columns` 배열 맨 위에 추가합니다. `body` 는 문단 배열이며, 소제목은 `{ "h": "소제목" }` 으로 넣습니다.

```json
{
  "id": "2026-12-gaba",
  "title": "칼럼 제목",
  "date": "2026-12-01",
  "category": "유산균 연구",
  "author": "이연희",
  "summary": "목록과 검색 결과에 보이는 한두 문장 요약",
  "thumb": "images/column/2026-12-gaba.jpg",
  "body": ["첫 문단", { "h": "소제목" }, "다음 문단"],
  "references": [{ "label": "참고 논문", "url": "https://doi.org/..." }],
  "related": { "strains": ["pl186"] }
}
```

## 배포

- **GitHub Pages**: 저장소 Settings → Pages 에서 `main` 브랜치의 루트(`/`)를 지정합니다.
- **일반 웹호스팅**: `src/`, `docs/`, `_reference/`, `.claude/`, `.git/` 을 뺀 나머지를 그대로 올립니다.
- 실제 도메인이 `https://plbnb.com` 이 아니면 `data/site.json` 의 `baseUrl` 을 바꾸고 다시 빌드합니다. 검색엔진용 주소(canonical, sitemap)에 쓰입니다.

## 온라인 문의가 동작하는 방식

정적 사이트에는 문의를 저장할 서버가 없습니다. 그래서 두 가지 방식을 지원합니다.

1. **메일 방식(현재 설정).** 방문자가 양식을 채우면 방문자 PC의 메일 프로그램이 열리고, 방문자가 직접 보내기를 눌러야 접수됩니다. 화면에도 그렇게 안내하며 「접수 완료」라고 표시하지 않습니다. 메일 프로그램을 쓰지 않는 방문자에게는 불편할 수 있습니다.
2. **전송 방식.** `data/site.json` 의 `inquiry.endpoint` 에 폼 수신 서비스나 자체 서버 주소를 넣으면 그 주소로 전송하고, 서버가 정상 응답한 경우에만 「접수되었습니다」를 표시합니다. 첨부파일 칸도 이때 나타납니다.

자체 서버를 두는 경우의 설계는 [docs/관리자_백엔드_설계.md](docs/관리자_백엔드_설계.md) 에 정리했습니다.

## 쇼핑몰 연결

`data/site.json` 의 `shop.url` 이 비어 있으면 「준비 중」 안내 페이지로 연결됩니다. 공식 쇼핑몰 주소가 정해지면 넣고 다시 빌드하면, 모든 페이지의 메뉴가 새 창으로 열리는 외부 링크로 바뀝니다.
